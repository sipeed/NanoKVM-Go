# KVMGo device USB HID notes

These files are patched on the KVMGo device and are not owned by this
repository:

- `/opt/scripts/usbdev.sh`
- `/opt/scripts/usb-gadget.sh` (kept in sync when present, but `usbdev.service`
  currently starts `/opt/scripts/usbdev.sh`)

## hidg2 absolute input and multi-touch

`hid.GS2` carries four top-level collections on one interface. The report length
is 62 bytes so the touchscreen report can hold ten contacts; shorter reports are
still accepted by the HID gadget driver for the mouse and stylus collections.
Byte 0 is the report ID and selects the collection. Hosts create an input device
only for the collections they understand, so no host detection is needed on the
gadget side.

The following collection table describes the HID capabilities. Actual usability also depends on the
client browser platform and the remote host; see `docs/input-router.md` for the current tested client
matrix.

| Collection               | Function                                | Current tested use                                                |
| ------------------------ | --------------------------------------- | ----------------------------------------------------------------- |
| ID 1: GD absolute mouse  | Follow-pointer mouse                    | Windows and macOS clients; iPad without Assistive mode moves only |
| ID 2: digitizer stylus   | Android-compatible follow-pointer mouse | macOS and Android clients                                         |
| ID 3: multi-touch screen | Multi-touch screen                      | Windows and Android clients                                       |

The web UI maps mouse modes to report IDs: `absolute` sends report ID 1,
`digitizer-stylus` sends report ID 2, `relative` uses `/dev/hidg1` only.
`touch-screen` sends report ID 3 with up to ten contacts.

`digitizer-stylus` is the canonical device/API name. Existing marker files and
browser probe arguments using the legacy name `absolute-android` are accepted
and normalized to `digitizer-stylus`; the UI label remains unchanged for now.

### Report ID 1: absolute mouse

- byte 0: report ID `0x01`
- byte 1: buttons, bit 0 left, bit 1 right, bit 2 middle, bit 3 back, bit 4 forward
- byte 2-3: absolute X, little-endian, logical range `0..32767`
- byte 4-5: absolute Y, little-endian, logical range `0..32767`
- byte 6: wheel, signed int8

### Report ID 2: digitizer stylus

- byte 0: report ID `0x02`
- byte 1: state, bit 0 tip switch, bit 1 in range, bit 2 barrel switch
- byte 2-3: absolute X, little-endian, logical range `0..32767`
- byte 4-5: absolute Y, little-endian, logical range `0..32767`
- byte 6: tip pressure `0..255`

On the validated Android 16 target, Android classifies this collection as an indirect
pointer/stylus and applies one geometric scale to both logical axes. This is observed
Android `InputReader` behavior, not a USB HID guarantee or a promise that every Android
vendor uses identical calibration. The browser now sends the complete normalized content
coordinate without applying an additional aspect-ratio compensation. Device-specific
`.idc` calibration, display routing, OEM input changes, or a browser-side four-point Profile
can therefore determine the final behavior.

The touchscreen report ID 3 is different. Android classifies it as a direct touchscreen
and independently maps raw X and Y to the associated display viewport. On the validated
target that viewport is the external `3840x2160` display. A portrait image centered at
full height therefore occupies approximately X `0.372..0.628`; those values identify the
visible content boundaries within the complete external display and are not short-axis
stylus compensation.

### Descriptor hex

`report_length` is 62 for the composite `hidg2` function. Collection 1 (GD mouse, report ID 1):

```text
05 01 09 02 a1 01 85 01 09 01 a1 00 05 09 19 01
29 05 15 00 25 01 75 01 95 05 81 02 75 03 95 01
81 03 05 01 09 30 09 31 15 00 26 ff 7f 75 10 95
02 81 02 09 38 15 81 25 7f 75 08 95 01 81 06 c0
c0
```

Collection 2 (digitizer stylus, report ID 2):

```text
05 0d 09 02 a1 01 85 02 09 20 a1 00 05 0d 09 42
09 32 09 44 15 00 25 01 75 01 95 03 81 02 95 05
81 03 05 01 09 30 09 31 16 00 00 26 ff 7f 36 00
00 46 ff 7f 75 10 95 02 81 02 05 0d 09 30 15 00
26 ff 00 75 08 95 01 81 02 c0 c0
```

Collection 3 is a ten-contact digitizer touchscreen with report ID 3 and
collection 4 is its Contact Count Maximum feature report (ID 4). The complete
descriptor is generated by `configure_hid2` in `usbdev.sh`.

Deploy line used in the gadget scripts (both collections concatenated):

```sh
echo 62 > functions/hid.GS2/report_length
# Use configure_hid2 from /opt/scripts/usbdev.sh to generate the synchronized descriptor.
```
